# 개선 TODO

우선순위는 P0(즉시 위험 확인·차단), P1(고위험 결함), P2(품질·운영 개선) 순이다.
표의 작업은 열린 항목만 담는다. 완료 항목과 검증 근거는 [검증 기록](verification.md)에 둔다.
확인된 코드 결함, 추가 검증 가설, 저장소 밖 운영 조치를 구분한다.
독립 구현·로컬 검증이 가능한 부분은 계속 수행하고, 사용자 결정·실제 운영 검증이 필요한 부분은
아래의 경계를 유지한다. 구현한 제어의 운영 적용 성공을 미리 가정하지 않는다.

## 판단이 필요한 조건

- 배포할 Next.js 버전과 운영 Node.js·Linux libc 환경, 현재 배포 커밋을 확정한다.
- 공개 첨부 열람 정책과 기존 업로드 데이터의 이전 방법을 정한다.
- CSP의 외부 이미지·미디어 허용 범위를 실제 콘텐츠와 함께 정한다.
- 라이선스와 저장소 밖 프록시 변경은 소유자 결정 후 별도 수행한다.
